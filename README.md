# 跨境义诊器材交接

海外医疗行动跟踪便携筛查设备、无菌耗材、校准和返程结存。系统对交接记录执行**严格版本边界**、
**原子导入**、**数量/序列号守恒**与**离线乱序回执的幂等处理**。

## 版本边界（fail-closed）

加载器当前合同版本为 `schema_version = 2`（见 `contracts.CURRENT_SCHEMA_VERSION`）：

| 记录版本 | 处置 |
| --- | --- |
| **当前版本 v2** | 严格核对设备（标识、序列号、数量一致、校准时点）、耗材（标识、批号、数量、白名单单位）、交接场合与交接人，通过后才结算。 |
| **受支持旧版本 v1** | **只能显式迁移**：`load_document(path, migrate=True, migrator=...)`。v1 仅有版本中立信封，迁移结果是零移动 v2 记录并留下迁移记录，绝不凭空补造库存。未显式许可时抛 `MigrationRequiredError`。 |
| **超前版本（如 v99）** | 绝不按本地规则解释其校准含义或耗材单位。`seal_document` 封存**原文 + 中性摘要 + SHA-256**，标记 `AWAITING_UPGRADE`，等待加载器升级。 |

事故根因（v99 被 `DomainRecord(**payload)` 照常接纳）已消除：任何入口都先过版本边界。

## 守恒与生命周期

`ledger.InventoryLedger` 在每次应用交接后强制：

- **设备序列号守恒**：一件设备一个序列号，经借出引入后在跨站点转运、现场耗用、污染隔离、
  返程之间只改变保管节点与状态，绝不凭空产生或消失。现场耗毁的设备序列号留在耗用节点可追溯。
- **耗材批号守恒**：`接收总量 = 各节点可用 + 各节点隔离 + 现场耗用`，单位在引入时锁定，
  中途改写单位（如 `box`→`piece`）直接判矛盾。
- **校准最小冻结**：校准在任务途中到期只冻结受影响单台设备；冻结设备“可运不可用”，
  已完成检查一条不删；显式签发的替代设备按冻结序列号幂等，恢复后不重复生成。

## 安全导入与离线回执

`service.MissionService`：

- 每次接纳新事件都从**已接受事件全集**按时间确定性重建台账投影，成功后才经
  `os.replace` **原子整体落盘**；任何校验/冲突失败，旧状态原样保留，**不存在部分写入**。
- 离线回执（`receive_receipt(event_id, payload)`）：
  - 同 `event_id` 同内容 → 去重忽略；同 `event_id` 异内容 → **进入复核**，不二选一入账。
  - 保管链断裂（前置回执未到）→ 暂存，前置到达后按业务时点自动重试排空。
  - 硬矛盾（单位/状态/超量返程等）→ 进入复核，库存不动。
- 进程恢复后从状态文件重放同一事件集：**不重复扣减耗材、不重复生成替代设备、不重复通知**
  （通知去重键先持久化再发送，满足至多一次）。

## 最终清单

`report.build_final_report` / `render_text` 输出返程清单，每个差异都标注：

1. 采用的合同版本；
2. 迁移记录（from/to、迁移人、说明；当前版本直接核对则为空）；
3. 实际保管节点与状态。

并单列：待升级封存件、待人工复核冲突、仍等待前置回执的暂存项，以及耗材批号守恒结论。

## 目录

```
src/mission_kit/
  contracts.py  版本边界、严格合同、v1→v2 显式迁移、超前封存
  errors.py     分型异常（含 UnsupportedVersion / MigrationRequired / 矛盾 / 保管缺口）
  ledger.py     设备/耗材守恒台账、校准冻结、替代设备
  store.py      temp+os.replace 原子状态存储与封存原文落盘
  service.py    导入门面、确定性投影、离线回执、恢复幂等、通知去重
  report.py     最终差异清单（版本/迁移/保管节点）
fixtures/
  equipment_handoff.json       v1 信封样例（需显式迁移）
  handoff_v2_current.json      v2 当前版本完整交接样例
  handoff_v99_future.json      超前版本封存样例（含未知单位/校准语义）
```
